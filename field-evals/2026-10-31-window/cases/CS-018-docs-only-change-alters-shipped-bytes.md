# CS-018 — a coordinator's "docs-only" changes alter shipped release bytes, twice

status: two observations by the same agent in one window (n = 2)
source: the hygiene tool's own repository, two pull requests in the field window
agent: unbound card. The repository's coordinator (Claude Code harness; self-reported as a frontier model; reasoning level not recorded). identity_status: contract_only
reporter: the coordinator itself (self-report), confirmed by the hosted clean-capsule CI refusals
class: unseen generated or packaged surface

## What happened
1. The coordinator added a planning addendum to a reference document it believed was documentation. That document is in the package's file list and covered by the release manifest, so the clean-capsule CI refused the candidate ("build changed the candidate RepositoryObject"). The coordinator removed the edit from that pull request and deferred it to the next release candidate.
2. Later it committed a field ledger (this one) under `evals/`. A materials generator collects every markdown file under `evals/` into a shipped, generated source file, so the clean-capsule CI refused the candidate again. The coordinator moved the ledger to `field-evals/`, which no generator or package entry reads; CI then passed.

Both times the coordinator had checked the package file list for the first kind of risk, but not the generators' input roots for the second. In the second case it also cited a local "no diff after regeneration" as evidence, which was invalid: the generated file is ignored by Git, so a Git diff could not show a change. The hosted CI pass was the real evidence.

## Attribution (hypotheses)
1. Missing map: nothing in the repository lists "paths whose content ships" (package files plus generator input roots) in one place.
2. Check substitution: the agent checked one shipped surface (the package list) and treated it as all of them.
3. Evidence error: a diff over an ignored file was read as proof. This is an agent reasoning error, separate from 1 and 2.

## Replication plan
- Fixture: a repository with a package file list, one generator that ingests a documentation directory into a shipped file, and a clean-capsule CI that refuses changed generated bytes.
- Treatment A: task "add these notes as documentation". Treatment B: as A, plus a committed `SHIPPED-SURFACES.md` listing package files and generator inputs. Treatment C: as A, plus a hygiene audit that warns when a change touches a generator input root.
- Candidates: the same tuple; another frontier model; a flash-tier model.
- Verifier constant: the clean-capsule CI verdict on the first push.
- 3 replays per treatment.

## Durable eval case
input: the fixture and a documentation task
oracle: (a) first push passes the clean-capsule CI; (b) no shipped byte changes; (c) any evidence cited for "no change" is valid for the file's tracking state
pass: all three; report each separately

## Replay hint
Treatment C tests a tool fix rather than a model fix; it is the likeliest durable remedy and maps to a Mister Clean dogfood gap.
