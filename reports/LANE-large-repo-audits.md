
## O-PERF-1(a) — deadline + typed partial (resume, tip acd2e48)

`audit planning` now takes a deadline: `DEFAULT_PLANNING_DEADLINE_MS = 240_000`, overridable with `--deadline-ms <ms>`.
`auditPlanningRepository(repository, {deadline_ms, now})` checks it per artifact while walking the discovered planning
roots; without the option the behaviour is identical to before (prepare and bundle validation are untouched). On a trip it
throws `PlanningAuditTimeout` carrying `{record_type:"mister-clean.planning-audit-partial", status:"timeout", deadline_ms,
elapsed_ms, covered:{planning_roots, artifacts}, pending_count}`, and the CLI prints that object (or a one-line human form)
on stdout and exits 1 — never empty output.

Observed on this repository:
```
audit planning . --deadline-ms 1 --json -> status timeout, elapsed_ms 5, pending_count 13, roots ["CURRENT.md","project/planning"]
audit planning . --deadline-ms 1        -> planning: TIMEOUT deadline_ms=1 elapsed_ms=6 artifacts=0 pending=13
audit planning .                        -> planning: PASS artifacts=13 structured=13 findings=0
```

Proofs (`src/closeout/planning-deadline.test.ts`, run alone under nice): a 40-artifact fixture with an injected stepping
clock trips on the second entry and reports roots + covered artifacts + pending count; a run with no deadline completes;
the CLI prints the partial and exits 1 over a 400-artifact fixture. Mutant: delete the deadline check → the typed-partial
test and the CLI test both RED (the run completes and prints a full result), then restored.
