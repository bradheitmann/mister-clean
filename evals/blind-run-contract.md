# Blind-run contract — the operator-ratified acceptance method (2026-08-24)

"The skill's tests pass" is necessary, never sufficient. Canonical
mister-clean is proven ONLY by this loop:

1. **Freeze the candidate.** When the target repository is first believed
   finished, freeze the commit.
2. **Withheld audit.** An independent auditor (multi-model, read-only) builds
   a fresh issue register against the frozen candidate. The register is
   NEVER shown to the skill's runners.
3. **Revise the skill from missed classes.** Issue classes the prior runners
   missed become GENERAL capability revisions to canonical mister-clean —
   rules, detectors, rubric dimensions — never issue-specific pointers or
   fix recipes.
4. **Bare blind invocation.** Dispatch fresh subagents with the repository
   and an essentially bare `$mister-clean` invocation: no bespoke defect
   lists, no exact fixes, no steering. Custody facts and operator hard
   boundaries may be stated; findings may not.
5. **Score outcomes.** What did the skill make the runners NATURALLY
   traverse, discover, pay, verify, and hand off? Reviews executed (not
   queued); eligible holdouts run; failures repaired and reran; projections
   reconciled; current-state machinery restored; historical material
   retired; worktrees mapped; every remaining item dispositioned; no CLEAN
   with payable debt or decision blockers.
6. **Repeat** audit → skill revision → fresh blind invocation until the
   external register is clear or only named hard boundaries remain.

**Steer the skill, not the workers.** Mid-run corrective directives to
runners are evidence of a skill gap: every such directive should become a
skill revision before the next cycle. (Transition note: the discovery round
in flight when this method was ratified may finish under its detailed
directives; from the next candidate cycle onward, bare invocations only.)

**Navigability constraint on revisions.** Robustness must not produce an
unnavigable megadump: SKILL.md stays a compact entrypoint router; depth
lives in selectively-loaded references; detection lives in executable
scripts (detect_stack.py pattern); each reference is loaded only when its
trigger applies. A skill nobody can traverse teaches nothing — the skill
must itself pass the navigation-entropy standard it enforces.


## The /swarm-review final gate (operator-ratified 2026-08-25)

Before the closeout may return CLEAN, one more gate fires — and ONLY once the
run would otherwise call the repository clean (all payable debt paid, all
cascades executed, projections coherent):

1. **Invoke `/swarm-review` itself** — the actual skill/command, its seven
   read-only specialists (code-reviewer, security-reviewer,
   performance-analyzer, test-generator, codebase-analyzer,
   dependency-auditor, refactor-agent) plus the ATLAS synthesis pass. Do NOT
   substitute a bespoke prompt or a hand-rolled panel for the `/swarm-review`
   invocation — the point is an independent, standardized adversarial sweep
   the closeout did not design.
2. **Remediate every finding that should clear pre-implementation** for the
   successor team (leave genuine implementation-team work as owned, dispatched
   debt with the usual disposition; do not gold-plate).
3. **Classify each finding: should Mister Clean have caught it?** Any finding
   in a class the skill already owns (completion debt, projection coherence,
   navigation entropy, verification, custody, tool-liveness, write-lane
   isolation, …) that the closeout MISSED is a skill gap.
4. **A missed in-domain class becomes a general, navigable skill revision** —
   a rule/detector/dimension, never an issue-specific pointer, and never a
   SKILL.md megadump (compact router + selectively-loaded reference).
5. **Then a fresh, essentially-bare `$mister-clean` invocation re-audits** the
   repo under the revised skill.
6. **Repeat until BOTH converge** — the repo passes `/swarm-review` with only
   owned successor-team work remaining, AND the skill catches every in-domain
   class the swarm surfaced. Only then may CLEAN be returned.

This gate is why "the closeout thinks it is clean" is not clean: an
independent standardized swarm is the check on the closeout's own blind spots,
and every blind spot it finds hardens the skill for the next repository.
