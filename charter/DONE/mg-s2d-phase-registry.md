# DONE: mg-s2d-phase-registry (one registry of detector families; decision D8)
Slice: the six detector families (planning_graph, public_safety, github_actions, repository_boundaries, semantic_boundary, language_policy) are written out by hand in eleven lists or orderings and branched on at a dozen sites, and those disagree (census at main caa59e9, kept privately as s2/CENSUS-s2d-2026-11-17.md). One list drops language_policy when a second pass reads an older bundle; two branch sites run or project any unknown family as semantic_boundary; the command line's receipt table repeats the registry by hand. This slice makes one data table the source of every such list, and turns each branch chain into a record keyed by that table's ids, so that the compiler refuses a family that has no entry. It also lands decision D8 on the second pass's baseline.

Design, fixed here so the proofs can name it:
- src/closeout/phase-registry.ts exports `PHASES`: one entry per family, in this order: planning_graph, public_safety, github_actions, repository_boundaries, semantic_boundary, language_policy. Each entry holds its id, its command-line audit kind, and, for a family that takes part in a closeout, its scope, command, current detector id and bundle file name. repository_boundaries has no closeout part: it is audit-only. The module is data only and imports nothing from the families.
- Derived from it, with no second literal: `CLOSEOUT_DETECTORS` (detector registry 6), `RECEIPT_FAMILIES`, the set of families a legacy bundle baseline may hold, the command line's receipt table (family to bundle file), the command line's set of audit kinds, and the family order in bundle-live-validation.ts.
- Detector registries 1 to 5 stay as frozen data keyed by version, with their digests.
- Each chain that branches on a family id becomes a record typed `satisfies Record<…>` over the registry's id type, in the file that owns the behaviour: the read-only entry functions (second-pass.ts), the receipt shape gate, rows and fingerprint projection (finding-anchors.ts), the result-shape validators and the fingerprint rows (detector-coverage.ts), and the root projections (bundle-detector-evidence.ts). The kind-to-entry dispatch of `runAudit` in cli.ts reads the registry for the kind and the family.
- Not changed: the order of completion debts in prepare.ts, and prepare.ts's per-family root-debt blocks. They are named under Out of scope.

Declared behaviour changes, each with a proof; everything else is byte-identical to the base:
- Δ1 (D8): with no `--against`, the second pass never takes a SECOND_PASS or VALIDATE receipt as its baseline. When no other receipt exists it stops with the existing message `no earlier receipt for this repository; pass --against <receipt_id|bundle>`. The base fell back to the latest receipt of any mode.
- Δ2 (D8): `--against` naming a VALIDATE receipt is refused with a typed error. A SECOND_PASS receipt named explicitly is still accepted, as the existing test asserts.
- Δ3: a legacy baseline read from a bundle keeps that bundle's language_policy execution. The base skipped it without a message.
- Δ4: an id that is not in the registry is refused by the entry dispatch and by the receipt projection. The base ran or projected it as semantic_boundary. No validated input reaches this; the tests reach it with a cast.
