# Owner decision 2026-11-04: local measurement stores rotate into sealed segments and keep everything

**Context.** Two semantic findings (SEM-STATE-8CF757A62803, SEM-STATE-C6FB0796C5F5) flag the invocation journal (`<state>/mister-clean/invocations.jsonl`, 2.7 MB / 8,443 lines on the maintainer's host) and the run-receipt store (`<state>/mister-clean/receipts/`, 35 receipts) as append-only state with no bound that is fully re-read on every use. Both are local-only measurement data (never tracked, never packaged): the journal reconciles which Mister Clean runs happened; receipts are how `second-pass` and the field study measure what a run found, cleared, missed or introduced.

**Decision (owner, 2026-11-04).** Keep everything; rotate. Each store keeps a bounded live segment; above a size cap the live segment is sealed (read-only, digest recorded) into a numbered segment and a new live segment starts. A small segment manifest lets each use read only the segments it needs. No segment is ever deleted by Mister Clean; total disk use grows by the records written, not by re-reads. Pruning by age was considered and declined (it would discard field-study measurements).
